# Development

## Prerequisites

- Python 3.11 or newer;
- Node.js with the built-in test runner;
- Deno;
- Supabase CLI for deployment only.

No frontend package install or build step is required.

## Workflow

1. Preview with `python3 serve.py`.
2. Add or update a contract test before changing behavior.
3. Run the validation block in `README.md`.
4. Exercise affected pages at 320, 375, 390, 430, 768, 1024 and 1440 pixels.
5. Stage only named files and inspect the staged diff.

## Cadence product media

- Use approved, populated-account product captures; never substitute invented interface imagery for feature proof.
- Keep source recordings and Blender scenes in the controlled marketing asset library. Commit only web-ready MP4/WebP derivatives under `assets/cadence/`.
- Validate `assets/cadence/source-capture-manifest.json` against the controlled source directory before rendering. Theme renders must keep the project, screen, lyric text, crop and in-app control fixed while only the theme changes.
- Keep `assets/cadence/workflow-capture-manifest.json` aligned with every hero and feature derivative. Each entry must point to a capture from the current app build and populated demo project; update both source and derivative checksums whenever that evidence changes.
- The native navigation mark is generated by `scripts/render_cadence_mark.mjs` from `apps/mobile/src/components/CadenceLogo.tsx`; do not substitute the square app icon.
- Export the approved Blender handset to GLB with the screen material named `MAT-F03V5-screen-b01-v8-library`. Optimise each public model with `gltf-transform optimize --compress draco --texture-compress webp`; the current files must remain below 250 KB.
- Keep the pinned model-viewer bundle and its licence in `assets/vendor/`. Do not replace it with a runtime CDN import.
- Keep the pinned Three.js module, addons, Draco decoder and licence in `assets/vendor/three/`; V3 must preserve its authored camera and must not load Three.js from a CDN.
- Render every feature inside the live handset. `cadence/phone-stage.js` attaches the verified screen recording only when its chapter becomes active, seeks it from scroll progress and updates both the base-colour and emissive material maps. Do not add loop, autoplay, fake pause controls or baked marketing copy.
- Use `cadence/v3-scenes.js` only for source-locked authored scenes. Desktop and mobile GLBs are distinct compositions, not responsive resizes. Keep mobile Themes at its 780:4000 normal-flow ratio, and dispose off-screen renderers before another V3 scene becomes active.
- Encode web derivatives as H.264/yuv420p with faststart, a six-frame GOP and no audio. `scripts/encode_cadence_scrub_media.sh` also removes simulator status chrome; `scripts/render_cadence_phone_batch.sh` performs the Blender handset render and bounded FFmpeg composite on Clevo.
- The feedback page uses its own optimised GLB and a verified still screen texture. Its existing cutout remains only as the poster fallback.
- Run Blender/FFmpeg batches on Clevo under `/home/luke/blender-cad-motion/cadence-website-v2/`; copy only final MP4/WebP derivatives back to this repository. Keep frame sequences, source recordings and derived `.blend` files on Clevo.
- Reduced-motion, `saveData` and unavailable-WebGL modes must not attach MP4 sources. The WebP poster is the complete fallback.
- Responsive product captures must set `height: auto` whenever CSS overrides their intrinsic width; HTML width and height attributes reserve space but must not distort the rendered image.
- Before release, confirm no horizontal overflow or broken media at every locked width; scroll forward and backward through every demonstration and prove every clip stays paused while only the active scene time changes. At 200% zoom confirm the form remains usable and all primary mobile targets are at least 44 pixels high.

Independent visual acceptance is mandatory. A verifier who did not author the renders must explicitly check text, screen, crop, theme, current in-app control, status chrome, aspect ratio and the absence of decorative boxes or invented UI.

## Feedback changes

Keep browser validation in `form-model.js`, transport behavior in `api-client.js` and DOM behavior in `feedback.js`. Mirror every browser constraint at the Edge Function boundary; client checks are user assistance, never authorization.

Schema changes require a new timestamped migration. Do not weaken RLS or add a public Storage policy to make uploads work—uploads use server-created signed tokens.

## Troubleshooting

- A clean URL returning 404 under `python3 -m http.server` is expected; use `serve.py`.
- If the form preserves answers but evidence fails, inspect TUS create/PATCH responses and then finalize status. Do not ask the tester to rewrite the response.
- If an import reports duplicates, compare only counts or hash prefixes in logs; never print participant rows during routine verification.
- If a price or plan changes, update the storefront. The website intentionally does not duplicate numerical pricing.
